## 2. 先更正我上一轮的错误：A04

按当前规则假设（2026–2027 年符合政策的新能源乘用车，含税价按 13% 折算）：

```text
车价：132,800 元
购置税：132,800 ÷ 1.13 × 5% = 5,876.11 元（最终展示到分）
14 万预算余额：140,000 − 132,800 − 5,876.11 = 1,323.89 元
```

**1,323.89 元正确；844 元是复核者的计算错误，作废。** 不应继续写“来源未确认”“可能预留保险”或并列两个有效答案。上一轮任务书已增加显式勘误并改正 A04。

也应删除“都远低于任何商业险报价”的无来源断言。正确结论是：尚有 1,323.89 元，保险、上牌等未报价，因此不能保证满足落地预算。

`expectation-review-v0.5.0.md` 的逐步示例还有一分钱的显示误差：11,752.21 − 5,876.11 不等于 5,876.11。算法保留中间精度、最后取整可以得到正确实缴数；示例应避免先展示已取整中间数再声称其减法精确相等。

位置：`test-cases.md:48`、`:49`、`:51`。

另：`expectation-review-v0.5.0.md` 把 Q18 描述成 14 万预算、Q19 描述成 13 万落地、Q21 描述成 14 万落地，与原题都不一致。审查报告应从真实题目生成题号/输入，不再手写另一份。

### P0-2 官方 PDF 可读取，但尚未证实适用于 2027 款当前条款

本次通过 HTTPS 直接下载 [官方 C11 告知书](https://ueapp-oss-static.leapmotor.com/pdf/web/service/C11_GZS.pdf)，确认：

- HTTP 200、396,119 字节、9 页；SHA256 与仓库登记完全一致。
- PDF `CreationDate` / `ModDate`：2022-10-14。
- 服务器 `Last-Modified`：2022-10-18 06:45:55 GMT。
- 正文没有明确标出 2027 款、当前生效日期或覆盖新款增程/纯电的说明。

这证明拿到了同一份官方文件，**不能证明文件已失效，也不能证明它适用于当前 2027 款两种动力**。采集日期 2026-11-11 不等于文件发布日期或生效日期。

`tests/answer-samples-v0.5.0.md:19` 先直接说“2027 款 C11 的整车质保……”，再在尾部说明不能确认最新版，顺序和结论不一致。S2 的营运条款、首保 3 个月/3,000 公里、救援与 200 元/天也应带同一适用限制。

建议表述：

> 官方域名中可读取一份 C11 基础服务告知书，其中记载这些期限和服务条件；其文件元数据为 2022 年，尚未确认适用于你购买的 2027 款及对应动力/批次。因此可用于了解该文件内容，当前购车承诺仍需适用协议或官方当期确认。

验收：来源卡新增文件时间/HTTP 元数据、适用年款与动力状态；所有用户可见样例同步限制。没有新证据前不能把补录状态写成“2027 款现行基础质保已确认”。

### P0-3 权益窗口的适用对象、期限含义不能混在一起

`ownership-and-order.md:63` 将“窗口期内下定并最终提车”解释为“窗口期内提车”。两者并不等价。必须回查原文，分别记录定金支付截止时间、提车条件及是否另有提车截止日；没写的截止条件不能增加。

应明确三个问题：

1. **现在新下定是否适用**：旧活动窗口已结束，当前是否有延续或新活动尚未确认。
2. **当时已满足领取条件的车主是否仍享有**：活动招募截止不等于已获得的终身/两年权益同期终止；依具体条款判断。
3. **该车主是否满足首任、非营运等持续条件**：与活动日期分别核验。

“终身质保不是条款”应改为“基础质保与附条件权益分别核实”。权益同样可以有条款；一份基础告知书没有某节，不能证明所有终身质保只能来自同一场历史活动。

软件流量表也要逐行注明适用活动批次和取得条件。不能只在较远段落说明窗口已过期，而在表中无条件写“C10/C11 终身免费、两年娱乐流量”。本次工具未能重新读取微信公众号全文，原文及条件仍须补可复核摘录；不得把本次文件审查说成该公众号已独立复核。

### P1-1 “只有名称带服务中心的店能保养”证据不足

门店名称、分类标签和具体授权能力不是同一字段。C11 告知书本身就同时提到服务中心与授权服务店。门店页能按服务类别筛选，不足以推出“体验中心一律不能”“交付中心一律不能”或“必须名称带服务中心”。

建议改为：**优先查询官方标注有售后服务能力的服务中心/授权服务店，并确认该店能否办理目标车型的首保、保修、三电检测和预约。单凭名称或体验标签不能确认。**

杭州索引快照可以保留为历史查询示例，不称实时名录；成都检索失败如实保留。某两个猜测的 PDF 地址返回 404，只能表述为“本次尝试路径未找到”，不能推出 C10/C16 告知书“未公开”或“应该存在但未挂出来”。

### P1-2 检查器还会接受来源越界与非法数据

原 7 类错误已被拒绝，值得保留。但独立补测发现以下输入仍能被 `validate()` 接受：负座位数、非数值电池容量、无效日期 2026-99-99、同一版本一条记录变成年款 1900、重复来源 ID、冲突主张清空来源等。

对三个关键场景，我在临时目录完成“修改 → validate → 重新生成 → check”，均仍返回 PASS：

| 反例 | 原因 | 应有行为 |
|---|---|---|
| 座位数改为 −3 | 只检查单位，未校验类型/值域 | 非法座位数拒绝 |
| C11 间接电池证据加挂无关 C16 官方来源，再把 evidence 改 direct | 覆盖检查只需任一来源覆盖，等级却取全部来源的最高等级 | 等级只取真正覆盖该版本字段的证据；无关来源不能抬升等级 |
| 给 C10 智享版填 confirmed/direct 的 8650 | 官方车型亮点来源的 `covers` 写成 c10-*，覆盖范围过宽 | 泛车型宣传不自动覆盖所有低配；将未证实归属排除或降级 |

修复顺序：先修“无关来源抬等级”和过宽 `covers`；再加数字类型/合理域、真日期解析、同版本元数据一致性、来源 ID 唯一性和冲突来源校验。`tax_applicable('2026-99-99')` 目前为 True，应拒绝非法日期；函数实际只检查日期窗口，也不能单凭 True 推出税收资格。

这不是要求检查器自动证明网页内容正确。机器应守住声明的结构、范围和等级；声明本身仍需证据审查。

### P1-3 降级必须出现在实际回答入口

43 条 `confirmed + indirect` 已在 JSON 中记录，但矩阵输出的电池、功率等仍只显示裸数值，SKILL 首选让模型查矩阵。没有逐字段提示，用户无法知道哪些值只来自间接证据。不能只凭记录在 JSON 里，就认定回答会披露限制。

验收：矩阵或紧邻的脚注对间接/媒体/未知/冲突标注到字段，并指向来源；SKILL 要求引用时携带该状态。来源卡里“有第二来源交叉”的说法也应落实到具体字段、第二 URL 和支持内容，不能用一句笼统保证替代。

## 4. 验证记录和交付表述应纠正

- `selftest` 实际为 **7 个错误场景 + 1 个基线 + 1 个合法更新**，共 9 行，不是 8 类错误。当前没有来源越界注入用例。统计从测试清单生成。
- `atest` 覆盖的是 **A01–A06、A10 中的数值/日期部分**，不是 A01–A14 的全部预期。它也未测试“模型拒绝错误推荐”等语言行为。
- `purchase-cost.md` 税表后的解释写“减半与减 1.5 万结果相同”，仍是错误句。正确是：这些车价对应的减税额未触及 1.5 万上限，故实缴恰为原税额的一半。
- “裸车价 + 全期贷款利息”的总成本不能标为“当期现金支出”。区分首期现金、全期还款、全期购车总支出及补贴到账，避免重复计本金或混用时点。
- 安装包里没有 Python 脚本，SKILL 也未约定运行计算工具。`budget_gap` 当前是仓库构建/检查能力，不是已验证的客户端能力。可以按宿主能力打包独立计算器并明确调用；受限客户端则输出显式算式、标估算，不能宣称程序保障了实际回答。
- `SKILL.md` / 客户端 F8 把 4915 与 4925 直接归因于年款，`model-c16.md:30` 却写“差异无法用年款解释”。先定位两方原始来源的具体年款；有证据才消解，暂时不能选一个新解释当定论。
- 原始 PDF 不分发，但 `docs/evidence/raw/C11_GZS.txt` 保存了全文提取内容。改扩展名不等于变成少量摘录。公开交付宜保留自写摘要、必要短引用、页码/段落、链接、哈希和元数据；全文本地留存或在明确许可后分发。此项不作法律合规已通过的认定。
