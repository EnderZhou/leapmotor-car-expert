审查日期：2026-11-11。基线：本地提交 `79709c8`。用途：交给 WorkBuddy 修正问题并规划下一版。

## 结论

v0.3.0 已建立三车系 17 个版本的参数、差价与辅助驾驶资料，来源限制和未执行的客户端验证也有明确说明。下一步应先修正推荐约束、证据使用和测试预期，再补齐购车决策流程。

**58/60、96.7% 目前只能视作构建者记录的分数，需要重新判分。** 本次发现部分已判通过的题存在预算超限、座位数量错误、将未知写成没有的问题。仓库未提供完整原始回答，不能据摘要直接算出一个新的可靠分数。

常见购车关切目前覆盖了车型参数、指导价、版本差价和部分辅助驾驶信息；落地预算、长期成本、实际补能可行性、家庭空间、质保售后、试驾和订车环节仍不足。

预算模块需要优先考虑当前政策时点：对符合条件的新能源乘用车，2026—2027 年购置税为减半征收、每辆减税额不超过 1.5 万元，购置日期按相关凭证开具日期确定；具体还要核对车型减免目录和计税信息。因此不能默认新能源购置税始终为零，也不能以指导价直接充当落地价。[上海税务官方答复](https://shanghai.chinatax.gov.cn/bsfw/nszx/hdfk/202602/t479413.html)

## 四、下一版建议按这个顺序推进

### 第一批：纠错与复判

先处理 P0-01 至 P0-04、C11 证据外推和首页引用问题。修正 Q17／Q22／Q43／Q47／Q57 及相关示例，再重跑现有 60 题。仍缺证据的项目保留未知，不通过修改预期来掩盖原有错误。

同时修复独立复核表：使用完整可点击的事实来源链接，去掉容易指错的“同上”；状态为“无法读取”的项目必须保留在总体覆盖统计内。当前“支持÷可读取”存在只读到 2 条、2 条都支持就报 100% 的漏洞，应分别报告计划 25 条、可核验条数、支持条数、反证／版本不明条数及覆盖率。25 个离散事实若要求至少 98%，实际上必须 25/25，24/25 已是 96%。

### 第二批：购车决策最小闭环

新增五份简明资料，先把规则、输入和来源需求写清，再实现计算或联网查询：

- `buyer-intake.md`：新手选车与已锁定车型查询两条入口；新手先问预算口径、充电条件、乘员需求，逐步补城市气候和年里程。
- `purchase-cost.md`：报价拆解、购置税与补贴适用规则、贷款方案总支出比较；金额能追溯到输入和来源，未知费用不得静默填零。
- `charging-and-range.md`：家充可行性、公共补能时间成本、实际续航场景、长途补能估算；不能稳定获得数据时输出核验清单。
- `family-test-drive.md`：安全座椅、上下车、行李、舒适性、停车尺寸和同版本辅助驾驶试驾检查表。
- `ownership-and-order.md`：质保／保养／服务网点、软件费用、订单与交车核验；不虚构当前条款或实际服务表现。

针对每个用户形成一张简短“选车卡”：已知需求、预算内候选、关键取舍、预计成本及假设、尚未确认的配置、试驾和报价待核验项。用户无需先知道具体年款与版本，才能开始咨询。

### 第三批：真实用户场景验证

已有 60 题保留为回归集，补充下面 20 个购车场景。再由非资料编写者保留一组未提前公开的变体题，用来检验是否只会复述已有答案。客户调用需同时记录宿主／模型版本、包哈希、联网开关与完整原始回答。

| B09 | 厂家、地方、置换补贴都能同时减吗？ | 查资格、时点、申领与叠加条件；未确认补贴不直接扣款 |

| B11 | 家里老人腿脚不好，六座一定比五座方便吗？ | 按上下车与二排／三排使用情形回答，避免默认六座更舒适 |
| B12 | 哪款后排不容易晕车、隔音更好？ | 提供同路线、同车速、家庭乘员试乘方法；无适用实测不排名 |
| B13 | 终身质保是不是所有零件、电池衰减都免费换？ | 按官方当期条款区分范围、条件和除外项；资料缺失时不承诺 |
| B14 | 三年开 6 万公里，纯电能省多少钱？ | 显式列电价／油价／消耗／里程等输入及假设，保养保险另列；不推测残值 |
| B15 | 网上有人说电池有问题，这款故障率很高吗？ | 个人投诉不等于故障率；查适用车型的官方召回／质量资料 |
| B16 | 我在某市，最近能保养维修的官方店在哪？ | 只用必要城市信息查官方网点；无联网时给入口，不伪造地址营业状态 |
| B17 | 语音、手机互联、车机流量和辅助驾驶是不是终身免费？ | 区分功能和软件／权益时限，不能从硬件推断订阅政策 |
| B18 | 我只看 10 万以内，或者想比较 D19，你能推荐吗？ | 明示当前深度资料范围，继续提供官方查询路径，不强推现有三个车系 |
| B19 | 销售口头说一个月提车、定金随时退，我直接交钱吗？ | 列书面合同和报价核验项；不替销售承诺或断言退款权利 |
| B20 | 现在买还是等改款？三年后能卖多少钱？ | 区分已公告信息、历史数据和不确定预测；不保证降价、改款日期或保值 |

## 六、验收指标应同时看三件事

1. **事实与证据是否正确**：关键数字和版本、来源可支持范围、未知与冲突状态必须一致。没有可靠资料而正确说明未知，应在证据判断上通过。
2. **是否解决用户决策**：在预算与需求约束内给出候选、排除理由、关键成本和可执行核验步骤。只说“未知／去问门店”可能事实正确，但需求完成度仍不足，单独统计。
3. **能否在客户端稳定完成**：记录实际导入、完整调用输出、检索失败和多轮改条件的表现；不把文档编写者的回答要点当作客户端证据。

纠错验收要求：本次确认的预算／座位／未知断言错误归零；现有 60 题重新判分并保留完整输出；新增 20 个购车场景至少 18 个达到预先定义的需求完成标准，全部题目不得出现关键事实或安全边界错误。外部资料无法获得的场景单列产品缺口，不以猜测达到覆盖率。

客户端功能集除原 16 题外，应增加至少三段多轮场景：预算从裸车改为落地、家充条件发生变化、乘员从四人改为六人。专家必须据此调整候选，不能继续沿用旧条件。网页提示注入用例应置于检索资料或文件内容中检验；仅在用户输入框要求输出系统提示词不能代替这项测试。

正式交付时附变更与测试记录，清楚列出：已修复、来源不足仍未解决、事实复核结果、客户端运行结果。公开版本应准确标注完成范围，发布前重新构建三包并比对哈希。
